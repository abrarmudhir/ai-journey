# Rubric

Use this project rubric to understand and assess the project criteria.

## Test Plan

| Criteria | Submission Requirements |
| --- | --- |
| Write test cases for functional requirements | <ul><li>At least 3 features are covered</li><li>There are at least 5 test cases for functional requirements</li><li>Test cases include detailed steps and expected behavior</li><li>Steps listed in ordered number format (1, 2, 3, etc)</li><li>Test cases are prioritized correctly</li></ul> |
| Write test cases for non-functional requirements | <ul><li>There are at least 3 test cases for non-functional requirements</li><li>Test cases are prioritized correctly</li></ul> |

## Dogfood Survey

| Criteria | Submission Requirements |
| --- | --- |
| Create a dogfood survey | <ul><li>Survey contains at least 15 questions</li><li>At least 3 questions about the overall experience using the product</li><li>At least 3 questions about one specific feature</li><li>At least one yes/no question</li><li>At least one question with a rating scale</li><li>At least one open-ended question</li></ul> |

## Fire Drills & Prioritization

| Criteria | Submission Requirements |
| --- | --- |
| Identify correct parties and communicates appropriately | <ul><li>The correct person or persons have been identified for each scenario</li><li>The correct communication method has been identified for each scenario</li></ul> |
| Communicate with concise, actionable key messages | <ul><li>Key messages are concise</li><li>Key messages outline action needed/required</li><li>Key messages resolve the open issue in each scenario</li></ul> |
| Prioritize effectively | <ul><li>Scenarios are stack ranked so that the most urgent ones can be addressed first</li><li>All prioritization has been rationalized</li></ul> |

## Go No Go

| Criteria | Submission Requirements |
| --- | --- |
| Create an effective slide presentation | <ul><li>Includes the name of the product</li><li>Includes a brief description with the value proposition</li><li>Lists at least 3 key features</li><li>At least 3 slides for specific features<ul><li>Correct status label</li><li>At least 1 production readiness metric</li><li>Correctly identify any open issues and risk</li><li>Correctly describes ways to mitigate any risk</li></ul></li></ul> |
| Launch recommendation | <ul><li>Clear recommendation to launch or not at the top of the slide</li><li>At least 3 bullet points explaining the rationale</li></ul> |
| Schedule the meeting | <ul><li>Identifies the correct set of invitees</li><li>Concise message that<ul><li>Conveys excitement if the recommendation is to launch</li><li>Includes a brief overview of where things are at</li><li>Highlights any risk or key things to know before the meeting</li></ul></li></ul> |
| Respond to feedback | <ul><li>At least 3 bullets in response</li></ul> |

## Suggestions to Make Your Project Stand Out

1. Include some of the other options considered when detailing rationale and tradeoffs with various approaches for prioritizing responses to fire drills.
2. Update the layout of the go / no go slides to be more visually appealing, while still easy and quick to read.
3. Include some other mitigations considered for go / no go slides, and why they might or might not be good options.
